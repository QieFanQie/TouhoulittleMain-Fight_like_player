> 车万女仆（Touhou Little Maid）附属模组：**把玩家操作对应的效果视作「动作」，作为女仆的可选项**。
> **「类玩家」＝ 效果同构，输入不同构** —— 不新增游戏内容，而是对既有内容**按新粒度重新索引**。

```
玩家侧：  输入事件 ──(隐式解码)──▶ 选中的操作 ──▶ 效果
          左键连点 4 下              "连击A"        4 段伤害

女仆侧：  决策     ──(显式选择)──▶ 原子动作   ──▶ 效果
          行为逻辑说"用连击A"        "连击A"        4 段伤害
```

| **P1** | **W23 物品参数提供者**（SA 种 / 枪型 / 聚晶类别 / 法术意图） | 让 `vectorOverrides` 真正命中；**只影响打分精度**，不影响"能不能做出来" |

> ⇒ 下一步不是继续打磨 ③，而是先把 ② 的动作数量堆到"值得决策"的程度。

> ★★ **第五轮补充的一条（比上面更硬）**：**候选集里不能有"注定做不出来"的东西。**
> 「失败不付费」这条语义是对的，但若候选集里存在注定失败的项，它就退化成**永久卡死**。
> ⇒ 判据：**任何会被选中但做不出来的动作，都必须在解析期挡下**（现已由
> `catalog/executors.json` 数据驱动地落地，并由 `GameLoopSelfTest §6d` 钉住不变量）。
