### 1.8 ★★ 为什么必须自备一把惰性 IWand（源码证据链）

DarkWand 有**三个入口**都会汇到 MagicResults：
onUseTick(:449→:488，按住时每 tick) · finishUsingItem(:549→:555，松手) · use(:571，**形参写死 Player**→:614)

而 MagicResults 的第一行是：

    if (spell != null && caster instanceof Player playerEntity) {   // ★ 763 行：硬门控在 Player
        ...扣魂 / 冷却 / 施法...
    } else {
        this.failParticles(worldIn, caster);                        // 白烟（:132，10~44 个 CLOUD 粒子）
        worldIn.playSound(..., SoundEvents.FIRE_EXTINGUISH, ...);   // 灭火音
    }

**⇒ 女仆不是 Player ⇒ 白烟 + 灭火音，且根本不施法。**

**关键推论（决定了要不要「移植」）**：

1. 只调 spell.mobSpellResult(maid, staff) ⇒ **不经过物品路径** ⇒ **没有白烟** ✅
   ⇒ **瞬发法术不需要任何移植**。
2. 但**以光束实体为载体的法术**（AbstractBeam）靠 isUsingItem() 存活 ——
   要求 isUsingItem() && 用着 IWand && 杖里有聚晶 三者同时为真。
3. ⇒ 要救这类法术就得 startUsingItem(MAIN_HAND)；
   而手上凡拿着 goety:dark_wand，这一步就会让原版去调 **DarkWand.onUseTick** ⇒ **白烟又回来了**。

> ⇒ **正解：自备一把 implements IWand 但 onUseTick 空实现的法杖** ——
> 它同时满足「正在使用 IWand」（光束能活）与「不触发 DarkWand 的任何副作用」。
> **这就是调律师 TunerWand 存在的唯一理由**（MIT ⇒ 可合法移植并注明出处）。

### 1.9 MIT 是什么

**MIT 是调律师（goety-tuner）的开源许可证**，也是最宽松的许可证之一：
可自由**使用 / 复制 / 修改 / 合并 / 发布 / 再授权 / 出售**，
**唯一要求是保留版权声明与许可证文本**。

⇒ 我们可以**合法地把那几行代码抄进自己的模组**（这正是 THIRD_PARTY_NOTICES.md 的用途）。
**「移植」而非「依赖」** 的好处：**用户不必额外安装调律师**。

### ✅ W25 【已完成】弓只拉不放

**问题**：起手之后没人在"蓄力够了"的时候放箭 ⇒ 观感是"女仆一直举着弓"。

**当时的修法**（⚠️ 已过时，见本节开头的提醒）：承诺到期时调 `ActionExecutors.finish`。

**现在的形态**（★ 正确形态）：
1. `ActionExecutors.execute` 起手蓄力并**登记在途状态**（`Phase.CHARGING`）；
2. 每 tick `ActionExecutors.tickInFlight(maid, gameTime)` 检查"蓄力够了没有"

4. `finish()` 仍在承诺到期时兜底（防执行器漏报导致永久半拉弓）。

### 6.1 ★ D6 详解：为什么满血单敌时她偶尔会"撤退&脱战"

**现象**（可复跑的证据）：`GameLoopSelfTest §8` 的恒定战况回放 —— 200 tick 内
`{maid_native:melee_swing=10, fight_like_player:disengage=2}`。也就是**每 100 tick 左右她想撤一次**。

**机制**（这是弹簧的**代价语义**在正常工作，只是强度没调好）：

1. `melee_swing` 的向量里有 **`MITIGATION_SURVIVAL = −0.1`** —— 它的含义是「贴身挥击**制造**了一点暴露代价」；
2. `DecisionCycle.commit()` 执行后 `p ← p − u_x`。**减去一个负数 = 加** ⇒ 每挥一刀，
   `p[MITIGATION_SURVIVAL]` 就 **+0.1**（"我越来越需要不被打到"）；
3. 而 `MITIGATION_SURVIVAL` 的忘却率 **λ 只有 0.01**（这是刻意的：残血时的生存需求不该 1 秒就消失）
   ⇒ 这个累积**很久不衰减**；
4. `disengage` 的向量是 `{SINGLE −0.8, AREA −0.3, MITIGATION +0.8, MOBILITY −0.9}`
   —— 当 `p[MITIG]` 涨到约 0.5~0.8 时，**它就成了最近邻** ⇒ 她撤退&脱战（还会清空目标，持续 5 秒）。

⇒ 所以这**不是 bug**：她确实"累积了暴露、想拉开一次"。问题在于**两处强度**：
① `melee` 的 −0.1 让它每刀都在累积；② `disengage` 的 `MITIG +0.8` 太"香"，且**脱离本身并不真的满足"不被打到"这个需求**（拉远只是换个位置）。

**三个可选修法（都不需要写新规则）**：

| 选项 | 做法 | 效果 |
|---|---|---|
| **A（推荐，改数据）** | 把 `disengage` 的 `MITIGATION_SURVIVAL` 从 **+0.8 → +0.3**（保留它"放弃输出"的负值代价与 `MOBILITY −0.9`） | 只有 `p[MITIG]` **真的高**（残血/被围攻）时它才会被选中；满血单敌时不再插进来 |
| B | 提高 `MITIGATION_SURVIVAL` 的忘却率（λ 0.01 → 0.05） | 顺手也让"残血后想自保"忘得更快 —— 可能**削弱**想要的手感，不推荐单独用 |
| C | 给 `disengage` 加前置（如 `selfHealthPct < 0.4`） | 直接有效，但**引入了规则**，与"用评分而不是规则"的哲学相悖 ⇒ 不推荐 |

> ★ 我倾向 **A**：一行数据、可离线断言（回放里的 `disengage` 计数应降到 0），且不改变"残血时会逃"的能力。
> 需要你一句"可以"，我就改。

## 7. 纪律（本项目已验证有效的做法）

| 做法 | 为什么 |
|---|---|
| ★ **每个里程碑都有离线自测**（现在 **9 个自测 / 401 断言**） | 弹簧、弹簧动力学、载体解析、清单加载、端到端、**步法**、**游戏侧回放**全部能在没有游戏的情况下断言（逐个数字见 [12 §8](12-项目参考.md)） |
| ★★ **端到端自测不自己塞输入** | ⚠️ 这条曾经被违反：`PipelineSelfTest` 自己调 `notifyCompleted()` ⇒ **缺输入永远不会失败**。⇒ 新增 `GameLoopSelfTest`，纪律是**只喂"游戏侧真的会给"的输入**（连冷却账本都与游戏共用同一个类） |
| ★★ **数据也要被审计**（承诺时长 / 前置可达性） | ★ **"数据缺字段"与"游戏侧没接线"都不会让任何断言失败** —— 这是 2026-09-30 那次"全绿却不工作"的根因 |
| ★ **校验脚本化**（一键脚本 **19 步**，含轴名对账、执行器覆盖、**承诺时长**、**前置可达性**） | 静默失效比崩溃更难查（轴名写错会被 Gson 静默忽略；`duration` 缺字段则门控直接失效） |
| ★ **未落地机制一律登记**（W1–W40） | "看起来支持其实没有"是最容易骗过测试的缺陷 |
| ★ **只用已核实的 API**；未核实的 `status=planned/blocked` | 猜错的调用要么编译不过，要么**静默做错事** |
| ★ **每次自我纠正都记录**（已 **32 条**，见 [13-更正记录与教训](13-更正记录与教训.md)） | 条目本身有价值：它们标出了容易重犯的陷阱 |
| ★ **`v_x` 必须手写**，但允许启发式初值 + `provenance` 标记 | 它编码"这招值多少"，无法从 `effects` 自动推导 |
