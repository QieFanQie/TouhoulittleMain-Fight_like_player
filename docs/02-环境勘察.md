### 4.2 攻击行为的实现粒度（关键）

【已查证】`TaskAttack.createBrainTasks()`（`TaskAttack.java:53-67`）返回 5 个 brain 节点：

```java
StartAttacking.create(this::hasAssaultWeapon, IAttackTask::findFirstValidAttackTarget)  // 选目标
StopAttackingIfTargetInvalid.create(...)                                                  // 弃目标
SetWalkTargetFromAttackTargetIfOutOfReach.create(0.6f)                                    // 走位
MaidMeleeAttack.create(20)                                                                // ★ 唯一的"攻击动作"
new MaidUseShieldTask()                                                                    // 盾
```

⇒ **`MaidMeleeAttack.create(20)` 是女仆近战的全部动作空间。** 一个固定 20 tick 冷却的通用挥击。**"是哪一招"这个信息在 TLM 里根本不存在。**

### 4.3 拔刀剑兼容（TLM 侧）

【已查证】`compat/slashblade/SlashBladeCompat.java` 全文只有 31 行，核心是：

```java
public static void swingSlashBlade(EntityMaid maid, ItemStack itemInHand) {
    if (isSlashBladeItem(itemInHand) && maid.getTask().getUid().equals(TaskAttack.UID)) {
        int roll = maid.getRandom().nextInt(60) - 30;                     // ← 随机
        AttackManager.doSlash(maid, roll, Vec3.ZERO, false, false, 1.0, KnockBacks.smash);
        itemInHand.getCapability(CapabilitySlashBlade.BLADESTATE)
                  .ifPresent(s -> s.setLastActionTime(maid.level.getGameTime()));
    }
}
```

⇒ 女仆用拔刀剑只有**一次随机角度的斩击**。而玩家有 20+ 种操作。**这正是你所说"退化子集"的最直接证据。**

### 5.1 ⚠️ 重要风险：本地 TLM 源码 ≠ 运行中的 jar，且重复 modid 会被静默丢弃

【已查证，来自 Closing Song 实例审计】

| 项 | 事实 |
|---|---|
| 官方 1.5.3 | `touhoulittlemaid-1.5.3-forge+mc1.20.1.jar`，24,413,134 B，SHA-1 `9097a2a57e7ed639bca072dd62e4a9257e86db89` |
| `Closing Song` 实例运行 | `touhoulittlemaid-1.5.3-modified-all.jar`，24,420,301 B（**+7167 B**），SHA-1 `abb542d0e13ab24284759b5638fb6ed099fe27ee` ⇒ **文件名、大小、哈希三者全不同 ⇒ 非官方重构建** |
| 同实例还躺着 | 官方 1.5.2（24,403,507 B，SHA-1 `5561eda3…`，**与 Modrinth 官方发布字节一致**） |
| 本机源码 `TouhouLittleMaid-1.20` | `mod_version = 1.5.3`，含 `compat/extracontainer`、`compat/tbackpack`，但**缺少** `MaidStartAttacking` / `MaidClearStaleAttackTarget` ⇒ **与运行中的 1.5.3-modified 也不字节一致** |

**为什么没有 Forge 重复模组崩溃**（纠正一个常见误解）：
Forge 1.20.1 的 `UniqueModListBuilder.buildUniqueList()` 按 modId 分组，组内 >1 时调 `selectNewestModInfo`，
**按版本降序取一个、只在 DEBUG 级别记一条日志**。只有**存活文件之间**才可能触发 `Duplicate mods` 异常。
本实例日志实证：

```
Found 2 mods for first modid touhou_little_maid, selecting most recent based on version data
Selected file touhoulittlemaid-1.5.3-modified-all.jar ... with version 1.5.3-forge+mc1.20.1
```

⇒ **官方 1.5.2 被静默丢弃，实际生效的是非官方改造版。**

> 📌 **一处"两份调研结论冲突"的记录（方法论价值）**：
> 枪械调查独立地写下「Forge 通常对重复 modId 直接中止加载 —— **未确认**（我没启动游戏）」；
> 而落幕曲审计给出了 **`debug.log` 的实测行**。⇒ **日志实证覆盖推断**。
> 这正是本项目证据等级（源码/字节码/日志 > 推断）的又一次应用：**"通常如此"不构成结论**。

**对本项目的三条设计含义**：
1. **只依赖 `api` 包**（与 `fight_feed_back` 同一原则）；**不要依赖 `compat/**` 与其它内部类**
   ——因为连"本机那份源码"都不是运行中的字节码。
   > ⚠️ **一处例外（已实证）**：`compat/gun/**` 这 19 个 class 经 `javap -p` 逐类比对（含 lambda 序号）
   > **与运行 jar 完全一致** ⇒ 该包的 `file:line` 引用可用。
   > 但这**只覆盖这一个包**，不推翻本条的整体警告（见 [01](01-操作清单.md) §7.1 末）。
2. **验收基准用官方 1.5.3**，不用 `Closing Song` 实例（它的 TLM 是改造版）。
3. 若将来必须在改造版上运行，需**单独反编译那份 jar** 再确认差异。

## 6. 复核用命令

```powershell
# 读取任意模组的 modid / 版本 / 依赖
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z=[System.IO.Compression.ZipFile]::OpenRead('<jar路径>')
$e=$z.Entries | Where-Object { $_.FullName -eq 'META-INF/mods.toml' }
(New-Object System.IO.StreamReader($e.Open())).ReadToEnd()
$z.Dispose()

# 列出模组的所有类
$z.Entries | Where-Object { $_.FullName -match '\.class$' } | Select-Object -ExpandProperty FullName

# 查看签名（JDK 17）
$javap='C:\Program Files\Eclipse Adoptium\jdk-17.0.20.8-hotspot\bin\javap.exe'
& $javap -p -classpath '<jar路径>' '<全限定类名>'
```

> ⚠️ 本机 pwsh 控制台会把非 ASCII 输出显示为乱码。**读中文请用 `read` 工具读文件**，或先写入文件再读，不要直接 `Write-Output`。
