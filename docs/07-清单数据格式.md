# 07 · 清单数据格式（Q3 决策）

> **这是 Q3「清单交付成文档还是数据文件」的决策记录。**
> **你授权我决定 —— 本文给出决定、理由、以及被否掉的选项。**
> **什么时候读**：想知道"清单为什么是 JSON / 怎么加一条"时；改 `catalog/` 数据之前先看 §5。
>
> 产物见 [`catalog/`](../catalog/)：一份 JSON Schema + **6 个动作数据文件**（77 条）
> + **三份配套数据**（`carriers.json` 载体规则 / `vectors.json` 评分表 / `executors.json` 执行器映射）
> + 使用说明（见 [`catalog/README.md`](../catalog/README.md)）。

---

## 1. 决定

| 项 | 决定 |
|---|---|
| **格式** | **JSON**（不用 YAML / TOML / Markdown / Java 枚举作为**权威形态**） |
| **权威来源** | `catalog/data/*.json` —— **数据是权威**，Markdown 是它的散文解释与推导 |
| **契约** | `catalog/schema/operation.schema.json`（JSON Schema draft 2020-12，编辑器可校验/补全） |
| **运行期形态** | **数据包（datapack）**：`data/<modid>/operations/*.json`，由 Mojang `Codec` 解析 |
| **第三方扩展** | 整合包作者/附属模组可**用自己的数据包追加或覆盖**条目，**不需重编译** |
| **热重载** | 走原版 `/reload`（数据包原生能力） |

---

## 2. 为什么是 JSON

### 2.1 四条正面理由

| # | 理由 | 说明 |
|---|---|---|
| 1 | **零新增依赖** | Mojang 的 `Codec` / `RecordCodecBuilder` + `JsonOps` 是原版自带。YAML 需要额外解析库（且要处理版本冲突），TOML 同理 |
| 2 | **与 MC/TLM 的既有约定一致** | TLM 的每女仆数据就是 Codec 驱动（`entity/data/inner/AttackListData.java` 用 `RecordCodecBuilder`，`TaskDataRegister` 收 `Codec`）；Goety 用 JSON 数据（`damage_type` / recipes）；拔刀剑用数据包 `advancements`。**本项目不该引入一种新的数据惯例** |
| 3 | ★ **数据包 = 免编译扩展**，这正是第二步的前提 | "可便捷搭建的行为逻辑架构"要求**改行为不用改代码**。数据包让整合包作者与附属作者都能扩表 |
| 4 | **`/reload` 热重载** | 数据包原生；调参不必重启游戏 |

### 2.2 JSON 的唯一缺点与对策

**JSON 不支持注释。** 而本清单天然充满"为什么"（隐藏前置、已知偏差、陷阱）。
对策是**把注释变成字段**：

| 手段 | 用法 |
|---|---|
| `note`（i18n 字符串/多语言对象） | 记录"为什么这样、有什么坑" |
| `evidence[].note` | 记录该条证据的含义（而不只是一个 `file:line`） |
| `doc_mismatch` 证据等级 | 显式标注"文档与代码不一致，以代码为准" |
| `docs/01-操作清单.md` | 长篇推导留在 Markdown（人读），JSON 只保留结论与出处 |

> ⇒ **这不是妥协，而是更好的分工**：JSON 给机器与校验器，Markdown 给人。

## 3. 被否掉的选项

| 选项 | 优点 | **否决理由** |
|---|---|---|
| **YAML** | 支持注释、人类可读 | 需要额外解析依赖；MC 生态里没有先例；缩进敏感的格式在**大量长中文文本**（本清单满是中文说明）下极易出错且 diff 噪音大 |
| **TOML** | Forge 配置的惯例，也支持注释 | 适合**扁平键值配置**，不适合本清单的**嵌套数组 + 多态字段**（`stateReq`/`cost`/`effects` 各是一组带 `type` 的联合类型）。会给 Codec 映射带来无谓复杂度 |
| **Markdown 表格（＝现状）** | 人读最方便、评审快 | ① 程序读不了，必须手写转换；② 改一处要同步多处；③ 无法校验；④ **无法作为运行期数据** ⇒ 第二步做不到"改行为不用重编译" |
| **Java `enum` / `record` 注册表** | 类型安全、IDE 友好 | ★ **这正是万法皆通的天花板**：31 个 `DirectSkill` 是枚举 ⇒ 加一个操作要改代码重编译。而且本项目的核心诉求是**让第三方能扩表**，枚举做不到 |
| **JSON5 / JSONC** | JSON + 注释 | MC 不解析它；要自带解析器 ⇒ 回到"新增依赖" |

## 4. 格式的三处刻意设计

> 这三处都是为了第二步（行为逻辑架构）能成立。

### 4.1 族 / 实例两级（`kind` + `params` + `familyOf`）

```
kind: "family"  →  必须有 params（参数名 → 取值域）
kind: "atomic"  →  若属某族，用 familyOf 指回
```

**作用**：把「124 个聚晶」压成「1 族 + 5 个变体维度 + 124 参数」，同时不丢"穷举所有可行操作"的要求。

> ⚠️ **由此产生两种"条目数"口径**，引用数字时必须说明：
> 拔刀剑 = **30 条记录**（29 atomic + 1 family）＝ **31 个操作实例**
> （SA·Success 与 SA·Jackpot 被压成 `slashblade:slash_art` 的 `timing` 参数）。
> **`docs/01` 的表格按"实例"计数，`catalog/` 按"记录"计数，两者都对。**

### 4.2 新增 `exclusivity`（互斥占用组）—— 这是本轮催生的字段

**为什么必须有**：铁魔法侧的真实瓶颈是**「同类法术书互斥」**（`IMaidSpellData.canAddSpellBook` 拒绝同类书
⇒ 默认只能装 1 本 ⇒ 同时只有 5~12 个法术可用）。

`preconditions` 表达不了"**同时**只能用 N 个"这种**全局占用**约束——它是逐动作判定的。
若缺口，决策层会选中互斥的动作组合。故新增：

```json
"exclusivity": [ { "group": "irons_spellbook_slot", "slots": 1, "scope": "maid", "note": {…} } ]
```

同类需求还有：召唤位、主手法杖、护符槽。

### 4.3 `effects` 必须能表达「改状态」而不只是「造成伤害」

仆从管理类操作（跟随/待命/警戒、命令移动、处死）**不造成伤害**，它们改变的是**目标实体的行为模式**。
若 `effects` 只有 `DAMAGE`，这类操作在清单里就没有位置。

因此 `effects[].type` 收进了 **`SET_AI_STATE` / `DESPAWN` / `TELEPORT` / `SUMMON` / `APPLY_EFFECT` / `REMOVE_EFFECT` / `DISPLACE` / `HEAL` / `TERRAIN`**。

## 5. 运行期怎么用（给实现阶段的约定）

```java
// 数据包位置
//   data/<modid>/operations/<任意名>.json
// 每个文件：{ "formatVersion": 1, "operations": [ … ] }

public record OperationEntry(
    ResourceLocation id,
    Kind kind,                       // ATOMIC / FAMILY
    ResourceLocation carrier,
    String sourceMod,
    Map<String, Domain> params,      // 仅 FAMILY
    List<Predicate> preconditions,
    List<StateReq> stateReq,
    List<Cost> cost,
    Duration duration,
    Interruptible interruptible,
    List<ComboDep> comboDeps,
    List<Exclusivity> exclusivity,
    List<Effect> effects,
    Reach reach,
    List<Evidence> evidence
) {
    public static final Codec<OperationEntry> CODEC = RecordCodecBuilder.create(i -> i.group(…).apply(i, OperationEntry::new));
}
```

| 约定 | 说明 |
|---|---|
| **`formatVersion` 必须校验** | 不匹配则**拒绝加载并报错**，不要静默忽略 |
| **剪枝** | `sourceMod` 对应的模组未加载 ⇒ **整族不注册**（这是"零硬依赖"的落地方式） |
| **`RC` 条目不注册** | 只作为文档/数据保留，便于日后重评 |
| **失败即降级** | 单条解析失败 ⇒ 记 WARN 跳过该条，**不影响其它条目**（与 `fight_feed_back` 的兼容层原则一致） |
| **覆盖顺序** | 后加载的数据包覆盖先加载的同 `id` 条目（便于整合包作者改默认值） |

## 7. 待你确认与否决的余地

| 项 | 我的决定 | 你可能想改的地方 |
|---|---|---|
| 格式 | JSON | 若你更偏好 YAML 的可读性，代价是新增一个解析依赖（可接受，但不是默认） |
| 运行期形态 | 数据包 + `Codec` | 若你希望做成**只读的编译期资源**（不暴露给整合包），那就是 `src/main/resources/data/...` 且不注册 reload 监听 |
| 是否允许第三方覆盖 | **允许**（后加载覆盖同 id） | 若不想让整合包改行为，可改为"只允许追加、同 id 冲突即报错" |
| `exclusivity` 字段名 | `exclusivity` | 备选：`occupancy`（更贴"占用"语义）、`slots` |
